# 時間 OCR：資料流與限制

## 來源與範圍

使用者指定獨立 `Yang-00712/Oc`，沿用 StrForge 對话中確認的「拍照框時間欄 → 由上往下 → 四位數轉時間 → 人工校正」需求。已讀原 StrForge README 的本機保存、CSV、測試與實體 iPhone 區分；那份文件沒有 OCR 程式或已訓練模型。此 OCR 為 Oc 新建，沒有把未存在的功能說成搬移成功。

參考 StrForge 已核對的經驗：大 WASM/內嵌字型增加首頁負擔；短硬逾時 fetch guard 曾讓實機重抓大檔；只拿舊入口配新 payload 不是有效升級測試。Oc 不使用 StrForge 二進位、字型、全域 fetch guard 或保存key。主要設計選擇是獨立小型靜態入口與按需 Worker。

## 執行路徑

使用者選圖 → 在裝置解碼與縮小（長邊最多1600px） → 拖曳 ROI 或輸入比例 → 裁切 → 使用者按辨識 → Module Worker → 下載並核對模型設定與權重 → 閾值/去除近全寬薄表格線 → 逐列切割 → 自動字距或等寬四格 → 每格中心化28×28 → CNN候選 → 時間規則驗證 → 校正頁 → 人工確認 → 本機草稿/選擇性教材 → TXT/CSV/剪貼簿。

辨識成功才取代既有草稿。取消、下載或 hash 失敗、90秒未完成時終止 Worker，不再嘗試無限重抓；使用者可手動重試。沒有用時間先後推測字跡：倒退只警告。

## 記憶體與保存

不保存整張原始照片；只保留本次操作影像與草稿縮圖。既有照片canvas被替換時縮回1px，Worker每次結束即釋放。原始圖片仍需先解碼，超大檔案/低記憶體裝置仍存在風險，不能以縮小後1600px宣稱解碼峰值已受完整限制。

IndexedDB名 `oc-time-v1`，`state`保存草稿與比例框，`samples`保存最多2000列教材。每次成功transaction才回報已保存；失敗保留畫面並提示先匯出。設定顯示的是JSON內容估算大小，不是瀏覽器全部使用量或RAM。自動暫存不等於永久備份。

## 模型與训练

初始模型是小型CNN，僅0–9。55,000訓練、5,000驗證、10,000未用於選模的測試圖，seed712；驗證集挑checkpoint。PyTorch參數以JSON輸出，JS只實作兩層convolution+ReLU+pooling及linear；32組PyTorch golden logits用於跨語言一致性驗證，不能取代完整精度測試。

完整數值見模型自帶metrics，不把MNIST分類結果外推至照片/四位時間。使用者沒有提供真實手写時間照片，尚無個人字跡準確率。

本版手機只推論，無訓練環境。已確認列可選擇儲存作教材，ZIP含`labels.json`及每列PNG。正式重新訓練須再校對字框/label並以不同紙張或拍照session分割資料，防止同頁樣本洩漏到測試集。本版不提供可直接吃整列ZIP做digit training的虛假一鍵入口。

## 已有能力與未承諾事項

已有：選圖/相機檔案入口、矩形ROI、比例模板、±15°傾角、自動列/指定列數、4digit、校正候選、合法時間檢查、人工確認、草稿、匯出和可選教材。

未做：自动找紙角、透視拉正、連筆序列模型、雲端OCR、個人微調、離線Service Worker、Safari原生相機與iPhone主畫面實機驗收。相機`capture`只是瀏覽器提示，實際UI以裝置為準。

測試須使用真實圖片與Worker，不把直接塞答案當OCR成功。MNIST拼接示例標示為示例；不作使用者字跡測量。
